# Milestone v1.0: Production Hardening

**Status:** SHIPPED 2026-04-11
**Phases:** 1-7
**Total Plans:** 23

## Overview

This milestone hardened the existing monorepo into a production-ready and open-source-safe baseline without changing its architecture. The work established OSS-safe repository hygiene and CI guardrails, secured live API boundaries, added automated verification across the active surfaces, improved worker reliability and observability, tuned the production runtime, and closed the final milestone gaps around view tracking and PR test protection.

## Milestone Summary

### Key Decisions

- Preserved the existing monorepo architecture and treated the effort as hardening, not rewrite.
- Prioritized public repo safety and API security before performance work.
- Standardized on shared server-side validation, auth, rate-limit, and error helpers for live routes.
- Used Vitest plus Playwright as the active-surface verification baseline, with real Redis/Postgres integration coverage where production behavior mattered.
- Closed milestone gaps with targeted follow-up phases instead of carrying known production blockers into archive.

### Issues Resolved

- OSS safety and publication hygiene for a public repository
- Split post-view tracking with duplicate buffering and persistence behavior
- Silent worker-failure risk and missing backlog visibility
- Missing PR enforcement for the critical test baseline
- Remaining public donation and newsletter mutation routes outside the shared hardening contract

### Issues Deferred

- BullMQ critical-dependency warning during the portfolio build
- Vitest `environmentMatchGlobs` deprecation migration
- NextAuth debug logging still enabled in the dev-style E2E runtime
- Broader observability expansion such as dashboards and centralized alerting
- Retirement execution for the legacy `frontend/` surface

### Technical Debt

- The shipped baseline is production-ready, but a few non-blocking warnings remain and should seed the next milestone.
- Phase directories remain in `.planning/phases/` as execution history and can be archived later with `/gsd-cleanup`.
