<threat_model>
- **T-2-01:** A malformed or unexpected request body reaches business logic because parsing and validation are inconsistent across routes.
- **T-2-02:** Risky user-controlled fields like HTML content, subject lines, filenames, or free-text comments are accepted without consistent normalization or sanitization.
- **T-2-03:** Hardening changes create drift where some high-risk routes still use raw `req.json()` plus ad hoc guard clauses while others use the new boundary helpers.

Mitigations required in this plan:
- Add a shared validation pattern grounded in existing repo usage (`zod` and current sanitization helpers).
- Apply it to the highest-risk public and admin mutation routes in scope.
- Keep handlers thinner after validation so later auth/error/rate-limit work attaches to a predictable boundary.
</threat_model>
