<threat_model>
- **T-2-04:** Admin and protected routes drift into inconsistent authz behavior because some use a shared helper, some use boolean-only checks, and some re-implement session/admin or owner/admin logic inline.
- **T-2-05:** Route protection changes accidentally depend on middleware behavior instead of remaining server-authoritative.
- **T-2-06:** The compatibility login route remains an undocumented shadow auth surface with weaker controls than the canonical NextAuth flow.

Mitigations required in this plan:
- Converge targeted route handlers onto one shared server-side auth/authz contract.
- Keep route security independent from middleware behavior.
- Harden the compatibility login route in a way that preserves NextAuth as the source of truth.
</threat_model>
